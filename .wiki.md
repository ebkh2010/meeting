# Project Summary
Vidara یک SaaS چندمستاجری است که فایل‌های جلسه (صوت/ویدئو و پیوست‌ها) را به Minutes ساختارمند تبدیل می‌کند و پردازش async شامل ترنسکرایب، تولید متن و چرخه بازبینی/قفل‌سازی را مدیریت می‌کند. در کنار جریان Minutes، چرخه‌ عمر فایل‌ها با نگهداری/بازیابی سازمانی (external storage) برای هر tenant کنترل می‌شود تا هزینه و ظرفیت storage اصلی کاهش یابد.

# Project Module Description
## Frontend
- تنظیمات
  - `src/pages/Settings.tsx`: نمایش بخش External Storage
  - `src/components/settings/ExternalStoragePanel.tsx`: تنظیم target خارجی (S3/WebDAV)، تست اتصال، و کنترل jobهای archive/restore با polling

- کلاینت مدیریت API
  - `src/lib/mgmt.ts`: خواندن/ذخیره تنظیمات external storage، تست connection، شروع jobها و دریافت وضعیت

## Backend
- آرشیو/restore جلسات (logic + orchestration async)
  - `routers/archive.py`: endpoints تنظیمات target، تست اتصال، شروع archive/restore، مشاهده وضعیت meeting و job با retry/ظرفیت‌بندی
  - `services/meeting_archive.py`: همگام‌سازی منابع، مسیردهی tenant-scoped در target، verify (download/checksum)، حذف/بازگردانی، و enforce retention
- Object Storage خارجی
  - `services/external_storage.py`: abstraction برای S3-compatible و WebDAV (streaming، checksum/verify، delete)
- Targetهای سازمانی
  - `models/org_storage_targets.py` + `data_models/org_storage_targets.json`: مدل/اسکیما کانفیگ per-org
  - `services/storage_targets.py`: ساخت کانفیگ اجرایی (prefix tenant-scoped، validate، mask secret)
- state فایل‌های آرشیوشده
  - `models/meeting_archive_files.py` + `data_models/meeting_archive_files.json`: نگهداری وضعیت per meeting/source

- پیکربندی runtime برای فرانت‌اند
  - `routers/runtime_config.py`: ارائه `GET /api/config` برای تزریق `PUBLIC_API_BASE_URL` از ENV به فرانت‌اند بدون rebuild

- Gateway برای دسترسی کنترل‌شده به storage داخلی
  - `deploy/oss-gateway/app.py`: API با auth مبتنی بر `OSS_API_KEY` برای مدیریت/پرساین upload و download به MinIO (ایجاد bucket، head/list/delete/rename، presign)

## Deploy/Operations
- Docker-based deployment با reverse proxy و HTTPS:
  - `deploy/docker-compose.yml`: سرویس‌های db، MinIO، backend، frontend، proxy (nginx)، و certbot
  - `deploy/nginx/*`: template های nginx برای HTTP/HTTPS بر اساس وجود certificate
- اسکریپت‌های عملیاتی:
  - `deploy/scripts/init-env.sh`: ساخت/ایمن‌سازی `.env`
  - `deploy/scripts/install.sh`: build و up، init-storage، healthcheck، و صدور/تمدید SSL
  - `deploy/scripts/init-storage.sh`: idempotent ساخت bucketها در MinIO
  - `deploy/scripts/backup.sh` و `deploy/scripts/restore.sh`: بکاپ دیتابیس و storage (tar.gz) و restore امن
  - `deploy/scripts/update.sh`, `deploy/scripts/status.sh`, `deploy/scripts/logs.sh`: عملیات نگهداری و عیب‌یابی

# Technology Stack
- Backend: FastAPI (async) + SQLAlchemy async + Alembic + PostgreSQL (scoping چندمستاجری)
- Storage:
  - MinIO برای storage داخلی
  - Object Storage خارجی (S3-compatible یا WebDAV) برای archive/restore
- Auth/RBAC: tenant-scoped principal
- Jobs/Async: اجرای پردازش‌های archive/restore و ثبت وضعیت در دیتابیس
- Frontend: React + TypeScript + Vite، RTL Persian، React Router، React Query، Tailwind CSS
- Deploy: Docker + Docker Compose، nginx reverse proxy، certbot برای TLS

# Usage
## Deployment (Docker)
1) پوشه `deploy` را آماده کنید:
- فایل `.env` را از روی `deploy/.env.example` بسازید یا با `bash scripts/init-env.sh` تولید کنید.

2) استقرار کامل:
- `bash scripts/install.sh`

3) عملیات‌های نگهداری:
- وضعیت: `bash scripts/status.sh`
- لاگ‌ها: `bash scripts/logs.sh [backend|frontend|proxy|...]`
- بکاپ: `bash scripts/backup.sh`
- restore: `bash scripts/restore.sh <path-to-tar.gz>`
- آپدیت: `bash scripts/update.sh`

## Local development (existing flow)
- مسیرهای قبلی دستور build/run پروژه برای backend و frontend از ویکی قبلی ادامه دارد (بدون تکرار).
