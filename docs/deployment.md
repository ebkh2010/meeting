# راهنمای نصب «ویدارا - نسخه جلسات» روی سرور مستقل

این راهنما برای نصب سامانه روی یک سرور اختصاصی (VPS یا سرور فیزیکی) با Docker
نوشته شده است. همهٔ اجزا داخل همان سرور اجرا می‌شوند و سامانه به هیچ سرویس ابری
بیرونی وابسته نیست. تنها موارد بیرونی، سرویس‌هایی هستند که خود مدیر سازمان در
پنل تنظیمات وارد می‌کند (ایمیل SMTP، پنل پیامک، مدل‌های هوش مصنوعی، مقصد آرشیو).

---

## ۱. پیش‌نیازها

**سرور:**

| مورد | حداقل | پیشنهادی |
|------|-------|----------|
| سیستم‌عامل | Ubuntu 22.04 یا Debian 12 | Ubuntu 24.04 |
| پردازنده | ۲ هسته | ۴ هسته |
| حافظه | ۴ گیگابایت | ۸ گیگابایت |
| فضای دیسک | ۵۰ گیگابایت | ۲۰۰ گیگابایت (بسته به حجم فایل صوتی جلسات) |

**نرم‌افزار:** Docker نسخهٔ ۲۴ یا بالاتر همراه افزونهٔ Docker Compose.

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker "$USER"   # سپس یک بار از سرور خارج و دوباره وارد شوید
docker compose version            # باید نسخه را چاپ کند
```

**دامنه و DNS:** دو رکورد `A` بسازید که هر دو به IP همین سرور اشاره کنند:

| نام | نوع | مقدار | کاربرد |
|-----|-----|-------|--------|
| `meetings.example.com` | A | IP سرور | خود سامانه (رابط کاربری و API) |
| `storage.meetings.example.com` | A | IP سرور | نشانی‌های امضاشدهٔ بارگذاری/دریافت فایل |

**فایروال:** فقط پورت‌های لازم برای دسترسی کاربران را باز کنید. این بسته روی
میزبان پورت‌های `7080` (سامانه) و `7443` (فایل‌ها) را منتشر می‌کند (متغیرهای
`APP_PORT` و `STORAGE_HOST_PORT`). دو چیدمان ممکن است:

- **TLS در لبه (پیشنهادی):** گواهی روی nginx میزبان یا CDN (مثلاً ابر آروان)
  نصب می‌شود و لبه به `127.0.0.1:7080` و `127.0.0.1:7443` پراکسی می‌کند؛
  پورت‌های `443` (و در صورت نیاز `8443`) روی لبه باز باشند.
- **TLS داخل کانتینر:** گواهی دستی در `deploy/nginx/certs` قرار می‌گیرد؛
  پورت‌های `7080` و `7443` باید از اینترنت باز باشند.

```bash
sudo ufw allow 22/tcp
sudo ufw allow 7080/tcp
sudo ufw allow 7443/tcp
sudo ufw enable
```

> پایگاه داده، فضای ذخیره‌سازی و بک‌اند هیچ پورتی روی میزبان باز نمی‌کنند و فقط
> داخل شبکهٔ داخلی داکر قابل دسترسی‌اند.

## ۲. نصب در چهار فرمان

```bash
git clone <نشانی-مخزن> vidara-meetings
cd vidara-meetings/deploy
bash scripts/init-env.sh     # ساخت فایل .env با کلیدهای تصادفی امن
bash scripts/install.sh      # نصب کامل + فعال‌سازی گواهی دستی SSL
```

اسکریپت `init-env.sh` دو پرسش می‌پرسد (دامنهٔ سامانه، دامنهٔ فایل‌ها — ایمیل
گواهی اختیاری است) و بقیهٔ کلیدهای حساس را خودش به‌صورت تصادفی می‌سازد. اسکریپت
`install.sh` سپس پیش‌نیازها را بررسی می‌کند، ایمیج‌ها را می‌سازد، سرویس‌ها را
بالا می‌آورد، باکت‌های فضای ذخیره‌سازی را می‌سازد، سلامت سامانه را بررسی می‌کند
و در پایان گواهی دستی SSL را (در صورت وجود در `deploy/nginx/certs`) فعال می‌کند.

پس از پایان نصب، نشانی سامانه را در مرورگر باز کنید و **نخستین سازمان و مدیر آن
را با فرم ثبت‌نام بسازید**. هیچ حساب پیش‌فرضی در سامانه وجود ندارد.

## ۳. متغیرهای محیطی

همهٔ تنظیمات در `deploy/.env` قرار دارند. نمونهٔ کامل با توضیح هر مقدار در
`deploy/.env.example` هست.

### کلیدهای حیاتی (بدون این‌ها نصب متوقف می‌شود)

| متغیر | کاربرد |
|-------|--------|
| `POSTGRES_PASSWORD` | رمز پایگاه داده |
| `JWT_SECRET_KEY` | امضای توکن نشست **و** رمزنگاری همهٔ اعتبارنامه‌های ذخیره‌شده |
| `MINIO_ROOT_PASSWORD` | رمز فضای ذخیره‌سازی فایل |
| `OSS_API_KEY` | کلید ارتباط داخلی بک‌اند با دروازهٔ ذخیره‌سازی |

اسکریپت نصب سه شرط را روی این کلیدها اجبار می‌کند: خالی نبودن، طول حداقل ۱۶
نویسه، و نبودن در فهرست مقادیر نمونه/قابل حدس. اگر شرطی نقض شود، نصب با پیام
فارسی روشن متوقف می‌شود.

> **هشدار دربارهٔ `JWT_SECRET_KEY`:** این کلید اعتبارنامه‌های SMTP، پنل پیامک،
> کلید مدل‌های هوش مصنوعی و اعتبارنامهٔ مقصد آرشیو را رمزنگاری می‌کند. اگر آن را
> پس از راه‌اندازی تغییر دهید یا گم کنید، این مقادیر قابل رمزگشایی نخواهند بود و
> مدیر هر سازمان باید آن‌ها را دوباره وارد کند. دادهٔ جلسات آسیب نمی‌بیند.

### تنظیمات دامنه

| متغیر | نمونه | توضیح |
|-------|-------|-------|
| `APP_DOMAIN` | `meetings.example.com` | دامنهٔ سامانه |
| `STORAGE_DOMAIN` | `storage.meetings.example.com` | دامنهٔ فایل‌ها |
| `APP_PUBLIC_URL` | `https://meetings.example.com` | نشانی کامل سامانه |
| `STORAGE_PUBLIC_URL` | `https://storage.meetings.example.com` | نشانی کامل فایل‌ها |
| `PUBLIC_API_BASE_URL` | (خالی) | خالی بگذارید تا تماس‌های مرورگر روی همان دامنه بمانند |

### تنظیمات عملیاتی

| متغیر | پیش‌فرض | توضیح |
|-------|---------|-------|
| `TZ` | `Asia/Tehran` | منطقهٔ زمانی همهٔ سرویس‌ها |
| `MAX_UPLOAD_SIZE` | `2048m` | سقف حجم بدنهٔ درخواست در reverse proxy |
| `PRESIGN_EXPIRES` | `3600` | مدت اعتبار نشانی امضاشدهٔ فایل (ثانیه) |
| `CORS_ALLOWED_ORIGINS` | (خالی) | منشأهای مجاز cross-origin؛ خالی یعنی فقط same-origin |
| `RECOVER_ORPHAN_JOBS` | `1` | بازگردانی کارهای AI نیمه‌کاره به وضعیت شکست پس از ری‌استارت |
| `STORAGE_PORT` | `8443` | پورت گوش‌دادن مسیر فایل‌ها **داخل کانتینر**؛ روی میزبان با `STORAGE_HOST_PORT` (پیش‌فرض `7443`) منتشر می‌شود |
| `APP_PORT` | `7080` | پورت منتشرشدهٔ سامانه روی میزبان |
| `STORAGE_HOST_PORT` | `7443` | پورت منتشرشدهٔ مسیر فایل‌ها روی میزبان |

> سقف حجم و مدت فایل صوتی جلسه، جدا از این مقدار، در خود سامانه و در زبانهٔ
> «سقف‌های بارگذاری» تنظیمات سازمان کنترل می‌شود. مقدار `MAX_UPLOAD_SIZE` باید
> بزرگ‌تر از آن باشد.

## ۴. معماری اجرا

```
        اینترنت (لبه: 443/8443 یا مستقیم: 7080/7443)
                              │
                       ┌──────▼──────┐
                       │    proxy    │  nginx (+ SSL در حالت گواهی دستی)
                       └──┬───┬───┬──┘
             ┌────────────┘   │   └────────────┐
             │                │                │
      ┌──────▼─────┐   ┌──────▼─────┐   ┌──────▼─────┐
      │  frontend  │   │  backend   │   │   minio    │
      │  (استاتیک) │   │ (FastAPI)  │   │  (فایل‌ها)  │
      └────────────┘   └──┬──────┬──┘   └──────▲─────┘
                          │      │             │
                   ┌──────▼──┐ ┌─▼─────────────┴──┐
                   │   db    │ │   oss-gateway    │
                   │ Postgres│ │ (قرارداد ذخیره‌سازی)│
                   └─────────┘ └──────────────────┘

    گواهی SSL دستی در deploy/nginx/certs یا خاتمهٔ TLS در لبه (nginx میزبان/CDN)
```

**نقش هر سرویس:**

- **proxy** — تنها نقطهٔ ورود. دامنهٔ سامانه را به فرانت و مسیر `/api` را به
  بک‌اند می‌فرستد، و دامنهٔ فایل‌ها را به MinIO. بافر درخواست خاموش است تا
  بارگذاری فایل‌های حجیم جلسه بدون مصرف حافظه انجام شود.
- **frontend** — خروجی ساخت‌شدهٔ رابط کاربری که با nginx سرو می‌شود.
- **backend** — FastAPI با `ffmpeg` و فونت‌های لازم برای پردازش صوت و خروجی
  اسناد فارسی. کارهای غیرهمزمان (رونویسی، پیش‌نویس صورتجلسه، آرشیو/بازیابی) روی
  جدول `jobs` با درصد پیشرفت و امکان تلاش دوباره اجرا می‌شوند.
- **db** — PostgreSQL؛ جدول‌ها در نخستین اجرا به‌طور خودکار ساخته می‌شوند.
- **minio** — فضای ذخیره‌سازی فایل جلسات. همهٔ باکت‌ها خصوصی‌اند و دسترسی فقط با
  نشانی امضاشدهٔ زمان‌دار انجام می‌شود.
- **oss-gateway** — همان قرارداد ذخیره‌سازی که کد سامانه با آن کار می‌کند را روی
  MinIO محلی پیاده می‌کند. به این ترتیب هیچ خطی از کد قابلیت‌ها برای استقرار
  مستقل تغییر نکرده است.
- **گواهی SSL** — به‌صورت دستی در `deploy/nginx/certs/` قرار می‌گیرد
  (`fullchain.pem` + `privkey.pem`)؛ صدور و تمدید را لبهٔ شبکه (CDN) یا ابزار
  certbot روی خود میزبان انجام می‌دهد. سرویس certbot داخل این بسته وجود ندارد.

## ۵. کارهای روزمرهٔ عملیاتی

همهٔ فرمان‌ها از پوشهٔ `deploy` اجرا می‌شوند.

```bash
bash scripts/status.sh              # وضعیت سرویس‌ها و نتیجهٔ بررسی سلامت
bash scripts/logs.sh               # لاگ همهٔ سرویس‌ها
bash scripts/logs.sh backend       # لاگ یک سرویس مشخص
bash scripts/backup.sh             # پشتیبان‌گیری کامل
bash scripts/restore.sh <فایل>      # بازیابی از پشتیبان
bash scripts/update.sh             # به‌روزرسانی نسخه
bash scripts/issue-ssl.sh          # فعال‌سازی/بازبینی گواهی دستی SSL
```

توقف و اجرای دوبارهٔ سامانه:

```bash
docker compose --env-file .env -f docker-compose.yml stop
docker compose --env-file .env -f docker-compose.yml up -d
```

## ۶. پشتیبان‌گیری و بازیابی

### پشتیبان‌گیری

`bash scripts/backup.sh` یک فایل `tar.gz` با مهر زمانی در `deploy/backups`
می‌سازد که سه بخش دارد:

- `database.sql` — دامپ کامل پایگاه داده
- `storage/` — همهٔ فایل‌های جلسات (صوت و پیوست)
- `env.backup` — فایل کلیدها، شامل `JWT_SECRET_KEY`

اگر دامپ پایگاه داده خالی باشد یا کپی فایل‌های فضای ذخیره‌سازی شکست بخورد،
اسکریپت با خطا متوقف می‌شود و فایل ناقص تولید نمی‌کند (پشتیبان ناقص هرگز
به‌عنوان «موفق» گزارش نمی‌شود). پشتیبان‌های قدیمی‌تر از ۱۴ روز به‌طور خودکار
پاک می‌شوند (با `BACKUP_RETENTION_DAYS` قابل تغییر است).

> فایل پشتیبان کلید رمزنگاری دارد؛ آن را با دسترسی محدود و **خارج از همین سرور**
> نگه دارید.

پشتیبان‌گیری شبانه با cron:

```bash
crontab -e
# هر شب ساعت ۲ بامداد
0 2 * * * cd /root/vidara-meetings/deploy && bash scripts/backup.sh >> /var/log/vidara-backup.log 2>&1
```

### بازیابی

```bash
bash scripts/restore.sh backups/vidara-backup-20260821-020000.tar.gz
```

اسکریپت پیش از هر تغییر، تأیید صریح («بازیابی») می‌خواهد، سالم بودن پشتیبان را
بررسی می‌کند، بک‌اند را در طول کار متوقف می‌کند، پایگاه داده و فایل‌ها را
برمی‌گرداند و در پایان سلامت سامانه را می‌سنجد.

اگر `JWT_SECRET_KEY` فعلی با کلید زمان پشتیبان‌گیری یکسان نباشد، اسکریپت هشدار
می‌دهد. برای بازیابی کامل اعتبارنامه‌های رمزشده، مقدار `JWT_SECRET_KEY` را از
`env.backup` داخل پشتیبان به `.env` منتقل کنید و بازیابی را دوباره اجرا کنید.

## ۷. به‌روزرسانی نسخه

```bash
cd vidara-meetings/deploy
bash scripts/update.sh
```

ترتیب کار: پشتیبان‌گیری اجباری ← دریافت کد جدید ← ساخت ایمیج‌ها ← جایگزینی
سرویس‌ها ← بررسی سلامت. اگر سلامت برنگردد، اسکریپت لاگ خطا و دستور بازگشت به
نسخهٔ قبل را چاپ می‌کند.

## ۸. تنظیمات درون‌سامانه‌ای پس از نصب

این موارد کلید محیطی نمی‌خواهند و مدیر هر سازمان آن‌ها را از رابط کاربری وارد
می‌کند (کلیدها رمزنگاری‌شده ذخیره می‌شوند و فقط ماسک‌شده نمایش داده می‌شوند):

| بخش | مسیر در سامانه |
|-----|----------------|
| کاربران و نقش‌ها | تنظیمات ← کاربران |
| ارسال ایمیل (SMTP) و پیامک | تنظیمات ← اعلان‌ها |
| مدل‌های رونویسی و زبانی، اولویت و جانشینی | تنظیمات ← هوش مصنوعی |
| سقف حجم و مدت بارگذاری | تنظیمات ← سقف‌های بارگذاری |
| مقصد آرشیو خارجی (S3 یا WebDAV) | تنظیمات ← استوریج خارجی و آرشیو |

## ۹. عیب‌یابی

| نشانه | علت محتمل | راه‌حل |
|-------|-----------|--------|
| نصب با پیام «متغیرهای حیاتی خالی هستند» متوقف می‌شود | فایل `.env` کامل نیست | `bash scripts/init-env.sh` یا پر کردن دستی مقادیر |
| فعال‌سازی گواهی SSL شکست می‌خورد | گواهی دستی در `deploy/nginx/certs` قرار نگرفته است | `fullchain.pem` و `privkey.pem` را در `deploy/nginx/certs` بگذارید و `bash scripts/issue-ssl.sh` را اجرا کنید؛ یا TLS را در لبه (nginx میزبان/CDN) خاتمه دهید |
| سامانه با HTTP کار می‌کند ولی HTTPS نه | گواهی دستی فعال نیست یا لبهٔ TLS تنظیم نشده | `bash scripts/issue-ssl.sh` برای حالت گواهی دستی؛ در حالت لبه، پیکربندی nginx میزبان/CDN را بررسی کنید |
| بارگذاری فایل حجیم قطع می‌شود | `MAX_UPLOAD_SIZE` کوچک است | افزایش مقدار در `.env` و `docker compose up -d proxy` |
| دانلود یا بارگذاری فایل خطای دسترسی می‌دهد | `STORAGE_DOMAIN` به این سرور اشاره نمی‌کند یا `STORAGE_PUBLIC_URL` با آن ناهمخوان است | یکسان‌سازی مقادیر در `.env` و `docker compose up -d oss-gateway proxy` |
| بک‌اند بالا نمی‌آید | رمز پایگاه داده یا کلیدها ناقص است | `bash scripts/logs.sh backend` |
| تنظیمات SMTP/پیامک/AI پس از بازیابی کار نمی‌کند | کلید رمزنگاری تغییر کرده است | انتقال `JWT_SECRET_KEY` از `env.backup` به `.env` و بازیابی دوباره |
| فضای دیسک پر شده است | فایل صوتی جلسات انبار شده است | آرشیو جلسات قدیمی از تنظیمات ← استوریج خارجی و آرشیو، و پاک‌سازی ایمیج‌های بی‌استفاده با `docker system prune -f` |

## ۱۰. نکات امنیتی

- فقط سرویس proxy پورت منتشر می‌کند (پیش‌فرض `7080` برای سامانه و `7443` برای
  فایل‌ها)؛ پایگاه داده و فضای ذخیره‌سازی از بیرون در دسترس نیستند.
- همهٔ باکت‌های فایل خصوصی‌اند و دسترسی فقط با نشانی امضاشدهٔ زمان‌دار است.
- اعتبارنامه‌های SMTP، پیامک، مدل‌های AI و مقصد آرشیو در پایگاه داده رمزنگاری
  می‌شوند و در پاسخ API ماسک‌شده برمی‌گردند.
- هدرهای امنیتی (HSTS، nosniff، SAMEORIGIN، Referrer-Policy) در پیکربندی SSL
  فعال است.
- دسترسی فایل `.env` روی `600` تنظیم می‌شود؛ آن را در مخزن Git قرار ندهید.
- هر عملیات مؤثر (تغییر تنظیمات، آرشیو، حذف، بازیابی) در گزارش رویدادهای سامانه
  ثبت می‌شود.
- روترهای الگوی پلتفرم (CRUD عمومی `‎/api/v1/entities/*` بدون احراز هویت، OIDC،
  ویرایشگر فایل `.env` و دروازهٔ مستقیم AI) در استقرار مستقل به‌طور پیش‌فرض ثبت
  نمی‌شوند. فعال‌سازی دوبارهٔ آن‌ها فقط برای محیط پلتفرم است و با متغیر
  `ENABLE_PLATFORM_ROUTERS=1` روی سرویس بک‌اند انجام می‌شود.
- کارهای AI که با ری‌استارت کانتینر نیمه‌کاره می‌مانند، هنگام بالا آمدن به وضعیت
