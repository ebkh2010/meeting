# شروع سریع نصب روی سرور خودم

این برگه فقط مسیر اصلی نصب را دارد. برای جزئیات بیشتر (معماری، عیب‌یابی کامل،
امنیت) به `docs/deployment.md` مراجعه کنید.

---

## ۱. سرور مورد نیاز

| مورد | حداقل | پیشنهادی |
|------|-------|----------|
| توزیع | Ubuntu 22.04 / Debian 12 | Ubuntu 24.04 |
| پردازنده | ۲ هسته | ۴ هسته |
| حافظه | ۴ گیگابایت | ۸ گیگابایت |
| دیسک | ۵۰ گیگابایت | ۲۰۰ گیگابایت (بسته به حجم صوت جلسات) |

---

## ۲. چه چیزی باید دانلود شود

**فقط دو مورد:**

۱. **کد پروژه** — از همین محیط، خروجی پروژه را دانلود کنید (دکمهٔ دانلود/انتشار
پروژه در نوار ابزار بالای صفحه؛ فایل ZIP کل مخزن). لینک دانلود اختصاصی حساب
خودتان است و از داخل همین صفحه ساخته می‌شود؛ لینک ثابت عمومی ندارد.

۲. **Docker + Docker Compose** — روی خود سرور با اسکریپت رسمی نصب می‌شود:

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker "$USER"   # سپس یک بار logout/login کنید
docker compose version            # باید شماره نسخه چاپ کند
```

مستند رسمی جایگزین: <https://docs.docker.com/engine/install/>

> هیچ فایل دیگری لازم نیست؛ پایگاه داده، فضای ذخیره‌سازی و گواهی SSL همه با
> Docker به‌صورت خودکار آورده می‌شوند.

---

## ۳. قرار دادن کد روی سرور

فایل ZIP را از کامپیوتر خود به سرور بفرستید و باز کنید:

```bash
# روی کامپیوتر خودتان
scp project.zip root@SERVER_IP:/opt/

# روی سرور
cd /opt
sudo apt-get install -y unzip
unzip project.zip -d vidara-meetings
cd vidara-meetings/deploy      # پوشهٔ کاری همیشه همین است
```

اگر پس از باز کردن ZIP پوشهٔ `deploy` را نمی‌بینید، یک سطح داخل‌تر بروید
(`ls` بزنید و پوشهٔ اصلی پروژه را پیدا کنید).

---

## ۴. رکوردهای DNS (قبل از نصب)

**دو نام میزبان لازم است** و هر دو باید به IP همین سرور اشاره کنند:

| نام | نوع | مقدار | کاربرد |
|-----|-----|-------|--------|
| `meetings.example.com` | A | IP سرور | سامانه (رابط کاربری و API) |
| `storage.meetings.example.com` | A | IP سرور | نشانی امضاشدهٔ فایل‌ها |

بدون این دو رکورد، صدور گواهی SSL شکست می‌خورد. با `dig +short نام-دامنه`
بررسی کنید که IP درست برگردد. پورت‌های ۸۰ و ۴۴۳ باید از اینترنت باز باشند.

---

## ۵. توالی دقیق نصب

```bash
cd /opt/vidara-meetings/deploy
bash scripts/init-env.sh     # ~۱۰ ثانیه
bash scripts/install.sh      # ۵ تا ۱۵ دقیقه (بار اول ساخت ایمیج‌ها)
```

`init-env.sh` سه پرسش می‌پرسد و شما باید **دستی** پاسخ دهید:

| پرسش | مقداری که می‌دهید |
|------|-------------------|
| دامنهٔ اصلی سامانه | `meetings.example.com` |
| دامنهٔ فایل‌ها | `storage.meetings.example.com` |
| ایمیل گواهی SSL | یک ایمیل معتبر خودتان |

بقیهٔ کلیدها (رمز پایگاه داده، کلید رمزنگاری، رمز فضای فایل، کلید داخلی
ذخیره‌سازی) خودکار و تصادفی ساخته می‌شوند. اگر می‌خواهید مقادیر را دستی
ببینید یا تغییر دهید، فایل `deploy/.env` را ویرایش کنید (نمونهٔ کامل متغیرها
در `deploy/.env.example`).

اگر می‌خواهید فعلاً بدون SSL نصب کنید: `SKIP_SSL=1 bash scripts/install.sh`
و بعداً `bash scripts/issue-ssl.sh`.

---

## ۶. ساخت نخستین حساب مدیر

حساب مدیر با **ثبت‌نام در خود سامانه** ساخته می‌شود؛ هیچ رمز پیش‌فرضی وجود ندارد.

۱. مرورگر را روی `https://meetings.example.com` باز کنید (صفحهٔ ورود).
۲. زبانهٔ **«ثبت‌نام سازمان»** را انتخاب کنید.
۳. این اطلاعات را پر کنید: نام سازمان، نام، نام خانوادگی، شماره موبایل،
   کد ملی، جنسیت، ایمیل (اختیاری) و رمز عبور.
۴. دکمهٔ **«ساخت سازمان و ورود»** را بزنید.

نخستین ثبت‌نام‌کننده به‌طور خودکار **مدیر سازمان** می‌شود و بلافاصله وارد
می‌شود. نام کاربری پیش‌فرض همان شماره موبایل است.

## ۷. چهار تست پذیرش پس از نصب

```bash
bash scripts/status.sh          # وضعیت و سلامت همهٔ سرویس‌ها
bash scripts/logs.sh backend    # لاگ زنده (Ctrl+C برای خروج)
```

| تست | چه کاری کنید | نتیجهٔ درست |
|-----|--------------|-------------|
| ۱. بالا آمدن سرویس‌ها | `bash scripts/status.sh` | پایگاه داده/ذخیره‌سازی/بک‌اند «سالم»، HTTPS «فعال» |
| ۲. ورود | خروج و ورود دوباره با همان حساب | ورود به داشبورد بدون خطا |
| ۳. ساخت جلسه | «جلسات» ← ثبت جلسهٔ جدید | جلسه در فهرست ظاهر و باز شود |
| ۴. آپلود فایل حجیم | یک فایل صوتی ۱۰۰ مگابایتی به جلسه اضافه کنید | نوار پیشرفت تا ۱۰۰٪ و سپس قابل دانلود |

اگر تست ۴ شکست خورد، `MAX_UPLOAD_SIZE` در `.env` را بزرگ‌تر کنید.

---

## ۸. تنظیمات لازم پس از ورود

همه در صفحهٔ **تنظیمات** (`/settings`) و در همین زبانه‌ها:

| زبانه | چه چیزی وارد کنید |
|-------|-------------------|
| هوش مصنوعی | کلید سرویس رونویسی (حرف / ElevenLabs / Whisper) و کلید مدل زبانی (DeepSeek / AvalAI / ChatGPT / Kimi) با ترتیب اولویت |
| ایمیل | تنظیمات SMTP سازمان (میزبان، پورت، کاربر، رمز، فرستنده) |
| پیامک | اعتبارنامهٔ پنل پیامک |
| سقف‌های بارگذاری | حجم و فرمت مجاز صوت و پیوست |
| استوریج خارجی و آرشیو | مقصد S3 یا WebDAV + دکمهٔ «تست اتصال» |
| کاربران | افزودن دبیر و اعضا |

بدون کلید هوش مصنوعی، سامانه کار می‌کند اما رونویسی و پیش‌نویس هوشمند فعال نیست.

## ۹. پشتیبان‌گیری

```bash
bash scripts/backup.sh                      # خروجی: deploy/backups/vidara-backup-*.tar.gz
bash scripts/restore.sh <مسیر فایل پشتیبان> # بازیابی
```

پشتیبان شبانه:

```bash
(crontab -l 2>/dev/null; echo "0 3 * * * cd /opt/vidara-meetings/deploy && bash scripts/backup.sh >> /var/log/vidara-backup.log 2>&1") | crontab -
```

> **هشدار جدی:** فایل `deploy/.env` و کلید `JWT_SECRET_KEY` را جایی بیرون از
> سرور نگه دارید. با گم شدن این کلید، اعتبارنامه‌های رمزشده (SMTP، پیامک،
> کلید AI، مقصد آرشیو) دیگر قابل رمزگشایی نیستند — حتی با داشتن دامپ کامل
> پایگاه داده. فایل پشتیبان خودش این کلید را در `env.backup` دارد، پس آن را
> مثل رمز عبور محافظت کنید.

## ۱۰. چهار خطای رایج

| خطا | علت | راه‌حل |
|-----|-----|--------|
| `Docker نصب نیست` یا خطای دسترسی | کاربر در گروه docker نیست | `sudo usermod -aG docker "$USER"` و یک بار logout/login |
| `صدور گواهی ناموفق بود` | DNS به IP سرور اشاره نمی‌کند یا پورت ۸۰ بسته است | با `dig +short دامنه` بررسی کنید، پورت ۸۰ را باز کنید، سپس `bash scripts/issue-ssl.sh` |
| `بک‌اند سالم نشد` | رمز پایگاه داده تغییر کرده یا حجم حافظه کم است | `bash scripts/logs.sh backend` را ببینید؛ `free -h` بزنید و در صورت کمبود swap اضافه کنید |
| آپلود فایل حجیم با خطای ۴۱۳ قطع می‌شود | سقف حجم پروکسی کوچک‌تر از سقف سامانه است | `MAX_UPLOAD_SIZE` در `.env` را بزرگ‌تر کنید و `bash scripts/install.sh` را دوباره اجرا کنید |

سایر دستورهای روزمره: `bash scripts/update.sh` برای به‌روزرسانی نسخه (خودش
قبلش پشتیبان می‌گیرد) و `bash scripts/init-storage.sh` برای ساخت دوبارهٔ
باکت‌های ذخیره‌سازی.
