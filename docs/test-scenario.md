# سناریوی تست کامل سامانهٔ «ویدارا — نسخهٔ جلسات»

- **نسخهٔ سند:** ۱.۰
- **تهیه‌شده برای:** تست پذیرش کامل پیش از عرضه (UAT + امنیت + بار)
- **مبنای دامنه:** `docs/mvp_feature_review.md` (فیچرهای F1–F23 و M1–M14) + پیاده‌سازی فعلی
  (`app/backend/routers/*`, `deploy/*`)
- **زبان/جهت:** فارسی، RTL

---

## ۰. هدف و دامنه

این سند یک **سناریوی تست انتها-به-انتها** برای سامانهٔ ویدارا تعریف می‌کند و پوشش
کامل زنجیرهٔ ارزش را هدف گرفته است:

> ثبت‌نام و سازمان → اعضا و نقش‌ها → تنظیمات (AI/ایمیل/پیامک/سقف/آرشیو) →
> جلسه و دستور جلسه → دعوت و حضور → آپلود صوت → رونویسی → پیش‌نویس صورت‌جلسه →
> گردش تأیید و قفل → مصوبات و اقدامات → خروجی Word/PDF/ICS → آرشیو خارجی →
> اعلان‌ها → جست‌وجو و داشبورد → سهمیه → Audit Log → امنیت → بار → عملیات.

**در دامنه:** تست کارکردی (UI + API)، تست منفی، تست امنیتی لایهٔ API، تست
غیرکارکردی (بار ۱۰۰ کاربر همزمان)، تست عملیاتی (بکاپ/بازیابی/به‌روزرسانی).

**خارج از دامنه:** کیفیت زبانی مدل‌های بیرونی (رونویسی/LLM) فقط به‌صورت
«آستانهٔ پذیرش» سنجیده می‌شود؛ جزئیات پنل پیامک/ایمیل تأمین‌کننده‌ها برون‌سپاری است.

**قانون طلایی تست:** هیچ نتیجه‌ای بدون شواهد پذیرفته نمی‌شود — برای هر کیس،
شناسهٔ درخواست (Request-ID)، اسکرین‌شات، لاگ سرور یا خروجی curl ثبت شود.

## ۱. محیط تست و پیش‌نیازها

### ۱.۱ استقرار

```bash
cd deploy
bash scripts/init-env.sh        # دامنه‌ها + کلیدهای تصادفی
bash scripts/install.sh         # بیلد، اجرا، باکت‌ها، healthcheck، SSL
bash scripts/status.sh          # باید: db/minio/backend سالم، HTTPS فعال
```

نشانی‌های محیط تست (نمونه — با مقدار واقعی خودتان جایگزین کنید):

|---|---|
| `https://meetings.example.com` | سامانه (UI + API) |
| `https://storage.meetings.example.com` | فایل‌ها با URL امضاشده |

### ۱.۲ بازیگران (پرسوناهای تست)

دو سازمان می‌سازیم تا **جداسازی مستأجر** در کل مسیر آزموده شود:

| کد | سازمان | نقش | نام | وظیفهٔ تست |
|---|---|---|---|---|
| A1 | آلفا | مدیر سازمان (`org_admin`) | سارا مدیر | تنظیمات، دعوت، تأیید/قفل، داشبورد |
| A2 | آلفا | دبیر جلسه (`secretary`) | علی دبیر | ساخت جلسه، دستور، آپلود، ویرایش صورت‌جلسه |
| A3 | آلفا | عضو (`member`) | مریم عضو | RSVP، مشاهدهٔ جلسه، اقدامات خود |
| A4 | آلفا | دعوت‌شده (در انتظار) | رضا جدید | پذیرش دعوت، تعیین رمز |
| B1 | بتا | مدیر سازمان | بابک | تست نشت داده از سمت مقابل |
| B2 | بتا | عضو | نگار | تست نشت داده از سمت مقابل |

> سازمان «آلفا» از ثبت‌نام واقعی ساخته می‌شود (A1)؛ «بتا» نیز مستقل ثبت‌نام
> می‌کند. هیچ دادهٔ مشترکی نباید بین آن‌ها دیده شود.

### ۱.۳ دادهٔ تست

| # | داده | کاربرد |
|---|---|---|
| D1 | صوت فارسی تک‌گویندهٔ ~۱ دقیقه، mp3، کیفیت مناسب (متن مرجع مشخص) | رونویسی سریع + سنجش نرخ خطای واژه |
| D2 | صوت فارسی ~۶۰ دقیقه (مکالمهٔ چندنفره) | تست بار واقعی، زمان پردازش، قطعه‌بندی |
| D3 | فایل `test.exe` و `doc.pdf` با پسوند نامجاز برای صوت | رد پیش از انتقال بایت‌ها |
| D4 | فایل mp3 بزرگ‌تر از سقف حجم سازمان | رد با پیام سهمیه |
| D5 | فایل `wav` / `m4a` / `mp4` معتبر | ماتریس فرمت‌های مجاز |
| D6 | پیوست PDF و تصویر (زیر سقف پیوست) | دستور جلسه |
| D7 | ایمیل واقعی قابل دریافت (برای A2/A3/A4/B2) | جریان دعوت، یادآوری، خروجی‌ها |
| D8 | دو مرورگر: یکی عادی، یکی ناشناس | تست نقش‌ها و نشست‌ها همزمان |
| D9 | کلیدهای واقعی: حرف (STT)، DeepSeek یا AvalAI (LLM)، SMTP تست، پنل پیامک تست | فاز ۳ |
| D10 | مقصد S3-compatible تستی (مثلاً یک MinIO دیگر یا bucket جدا) و/یا WebDAV | فاز ۱۱ آرشیو |

### ۱.۴ ابزار

- **UI:** مرورگر + DevTools (Network/Console) — هر قدم با شناسهٔ درخواست ثبت شود.
- **API:** `curl` یا Postman با مجموعهٔ اندپوینت‌های `/api/v1/...` (لیست کامل در Swagger `/docs`).
- **بار:** k6 یا Locust با اسکریپت ورود + فهرست جلسات.
- **مانیتورینگ:** `deploy/scripts/logs.sh backend` در طول فازهای ۷ و ۱۸.

## ۲. سناریوی جامع E2E — «روز در زندگی» (جریان خوش‌مسیر)

این روایت، ستون فقرات کل تست است؛ هر گام به کیس‌های فاز ۴ به بعد ارجاع دارد.
اگر هر گام شکست خورد، ادامهٔ زنجیره متوقف و نقص ثبت می‌شود.

1. **A1 (سارا)** ثبت‌نام سازمان می‌کند و خودکار مدیر می‌شود. *(TC-01)*
2. **A1** در تنظیمات: کلید حرف + کلید LLM را ثبت و «تست اتصال» می‌زند؛ SMTP و پیامک
   را تنظیم می‌کند؛ سقف صوت را ۵۰۰ مگابایت/۱۸۰ دقیقه می‌گذارد. *(TC-03)*
3. **A1** با ایمیل، **A2 (علی)** را به نقش دبیر و **A3 (مریم)** را به نقش عضو دعوت
   می‌کند؛ **A4 (رضا)** دعوت می‌شود. *(TC-02)*
4. **A2/A3/A4** دعوت را از ایمیل می‌پذیرند و رمز تعیین می‌کنند. *(TC-02)*
5. **A2** جلسهٔ «هیئت‌مدیرهٔ آلفا — تیرماه» را با نوع «هیئت‌مدیره» می‌سازد؛ دستور
   جلسهٔ ۴ آیتمی (عنوان/مدت/مسئول + پیوست D6) می‌چیند. *(TC-04)*
6. **A2** اعضا را به جلسه دعوت می‌کند؛ **A3** پاسخ «حاضر» می‌دهد. یادآوری ایمیل
   ۲۴ ساعته و ۱ ساعته بررسی می‌شود. *(TC-05)*
7. روز جلسه: **A2** حضور واقعی را ثبت می‌کند و وضعیت حد نصاب بررسی می‌شود. *(TC-05)*
8. **A2** صوت جلسه (D2) را با URL امضاشدهٔ مستقیم آپلود می‌کند؛ نوار پیشرفت تا
   ۱۰۰٪؛ «مهر رضایت» را تأیید می‌کند. *(TC-06)*
9. **A2** کار رونویسی را شروع می‌کند؛ وضعیت `queued → processing → done` با تأخیر
   حداکثر ۱۰ ثانیه در UI به‌روز می‌شود؛ متن قطعه‌بندی‌شده و پخش همگام. *(TC-07)*
10. **A2** تولید پیش‌نویس صورت‌جلسه را می‌زند؛ خروجی شامل خلاصه، شرح به تفکیک
    دستور، مصوبات و اقدامات با مسئول/مهلت می‌آید. *(TC-07)*
11. **A2** پیش‌نویس را ویرایش و نسخه‌بندی می‌کند، سپس «ارسال برای بازبینی»
    می‌زند. *(TC-08)*
12. **A1** بازبینی و **تأیید** می‌کند؛ **A1** قفل می‌زند. تلاش A2 برای ویرایش
    سند قفل‌شده خطای ۴۰۹/۴۰۳ می‌گیرد. *(TC-08)*
13. **A1** خروجی Word (docx) و PDF و فایل ICS را می‌گیرد؛ PDF دارای لوگو، حاضران
    و جدول مصوبات است. *(TC-10)*
14. **A1** مقصد آرشیو S3 را با «تست اتصال» تأیید و آرشیو جلسه را اجرا می‌کند؛
    فایل‌ها روی مقصد تأیید (checksum) و از استوریج اصلی حذف می‌شوند. *(TC-11)*
15. اعلان‌ها: ایمیل دعوت/یادآوری/آمادگی پیش‌نویس، پیامک اطلاع‌رسانی، اعلان
    درون‌برنامه‌ای با نشان نخوانده. *(TC-12)*
16. **A3** در نمای «اقدامات من» اقدام خود را می‌بیند و وضعیتش را تغییر می‌دهد.
    *(TC-09)*
17. **A1** جست‌وجوی «تصميم» و «تصمیم» و «تصمیم‌گیری» را اجرا می‌کند — نتایج یکسان.
    داشبورد با سه کارت و دو فهرست بررسی می‌شود. *(TC-13, TC-14)*
18. **B1** با حساب سازمان بتا وارد می‌شود و تلاش می‌کند جلسه/صوت/صورت‌جلسهٔ آلفا را
    از UI و با فراخوانی مستقیم API ببیند — همه‌جا ۴۰۳/۴۰۴. *(TC-17)*
19. **A1** از Audit Log رخدادها را فیلتر می‌کند: ورود، تغییر نقش، تأیید/قفل،
    دانلود و حذف صوت. *(TC-16)*
20. مصرف سهمیه (دقیقهٔ رونویسی) در تنظیمات/داشبورد بررسی و تطبیق داده می‌شود.
    *(TC-15)*
